### 第 5 轮 · 数据分析脚本

**Agent 动作**：编写 `＜project＞/scripts/analyze.py`，四段式流水线。

| 阶段 | 处理 |
|---|---|
| 加载 | 读 `Sheet2`，`日期` 转 datetime，按日期排序、去重 |
| 清洗 | 三项体检（缺失 / 重复 / OHLC 逻辑冲突）+ 非正价格与零成交检查 |
| 指标 | MA5/10/20/60、净值、回撤、对数收益、量比 20、年化波动、夏普、ZigZag 阶段 |
| 导出 | 写成 `window.BYD_DATA = {...}` 的 JS 文件（避免 `file://` 的 CORS 限制） |

**第一次运行结果**

```
[OK] 清洗后 242 行 -> <project>/site/assets/js/data.js
     区间涨跌幅 -23.43% | 最高 307.38 | 最低 185.25
     年化波动 26.94% | 最大回撤 -38.71% | 夏普 -1.11
     上涨 102 天 / 下跌 140 天 | 胜率 42.15%
     阶段划分 13 段 | 月度 12 个
```

**Agent 自检发现的 2 个分析质量问题**

1. **阶段划分过碎（13 段）**：初版用「收盘价是否站上 MA20」二分法，产生 13 个片段，
   且首段被标成「下行段」但实际收益 **+13.19%**——标签与事实矛盾。
   *修正*：改用 **ZigZag 拐点法**（反向幅度阈值 10%），并对比 8% / 10% / 12% / 15% 四档，
   10% 得到 4 段干净的趋势结构。
2. **指标重复计数**：`换手率` 与 `成交量` 的相关系数完全相同（都是 0.227），怀疑二者线性相关。
   *验证*：`换手率 / 成交量` 的变异系数仅 **0.35%**，确认是固定流通股本下的线性映射。
   *处置*：相关性分析只保留一个，并把这一发现写进「数据体检报告」展示给读者；
   同时用 `成交额 × 涨跌幅`、`成交额 × 振幅` 补位，避免信息冗余。

**修正后的阶段划分**

| 阶段 | 区间 | 天数 | 收益 |
|---|---|---|---|
| 上行段 | 01-03 → 02-01 | 17 | +16.75% |
| 下行段 | 02-01 → 03-16 | 32 | -22.76% |
| 上行段 | 03-16 → 07-31 | 92 | +16.25% |
| 下行段 | 07-31 → 12-20 | 97 | -31.75% |

### 第 7 轮 · 自测与缺陷修复（关键环节）

**Agent 动作**：用 Playwright 驱动本机 Chrome，以 `390×844 / DPR 3 / 移动端` 上下文打开
`file://` 页面，抓控制台并逐 Tab 截图。**首轮截图即暴露 2 个致命缺陷，后续又陆续发现 6 个。**

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 整页 **0 个 canvas**，图表全空 | `setup()` 内声明了 `var vm = null`，**遮蔽**了外层 `vm`，`vm.$refs` 恒为 `null`，`buildTab()` 直接 return | 改用 `Vue.getCurrentInstance().proxy`，在 `onMounted` 中赋值给独立变量 `inst` |
| 2 | 步骤条只显示第 1 步；单元格互相嵌套成一串 | in-DOM 模板里写了 `<t-step-item ... />` 自闭合。**HTML 不支持自定义元素自闭合**，浏览器把后续兄弟节点全部塞进第一个标签 | 扫描全文，把 **22 处**自闭合组件标签全部改为显式闭合 |
| 3 | 提示条只剩一个图标，文字消失 | TDesign 的 `t-notice-bar` **默认插槽不渲染**内容 | 改用 `content` 属性；前缀徽标用 CSS `::before` 补齐 |
| 4 | 成交量区被压到 13px 高；X 轴日期出现两组 | `Object.assign(默认值, axisCommon)` **合并顺序反了**，公共配置覆盖了 `axisLabel: {show:false}` | 改为 `Object.assign({}, axisCommon, overrides)` |
| 5 | 均线图例颜色与线条颜色不一致 | 只设了 `lineStyle.color`，图例取的是调色板默认色 | 同时设 `itemStyle.color` |
| 6 | 全屏弹层打开后图表空白 | 弹层内容经 Teleport 渲染，`$refs` 拿不到 | 改用 `document.querySelector('.zoom .chart')` |
| 7 | 区间胶囊选中态不生效 | 覆盖的类名 `.t-check-tag` 不存在 | 实际类名为 `.t-tag--checkable` / `.t-tag--checked` |
| 8 | 月度柱状图的数值标签跑进柱子内部，且负值标签挤在 0 轴附近 | 试图用 `label.position: function(){...}` 动态指定位置——**ECharts 的 `position` 不接受函数**，只有 `formatter` 接受 | 改为在 `data` 的每一项上单独挂 `label: { position: 'top' \| 'bottom' }` |

**此外还做了 3 轮视觉精修**（基于截图逐张比对）：

- 洞察卡片正文 11.5px → 12px、行高 1.68 → 1.72；加粗从「每句都粗」压缩到「每卡最多两处」；
- 阶段卡片原本一行长文本换行错位，改为 `flex-wrap` 的三段式元信息；
- 散点图去掉压在 0% 基准线上的「换手率 %」轴名，Y 轴范围收紧到 `[-6.5, 6.8]`。

## 三、关键决策摘要

| 决策点 | 选择 | 备选 | 理由 |
|---|---|---|---|
| 技术路线 | 零构建 + UMD 本地化 | Vite + npm | 题目要求「h5 静态页面」，且需离线可开；UMD 方案双击即用，无环境依赖 |
| 数据载体 | `window.BYD_DATA` 的 JS 文件 | 独立 `.json` + fetch | `file://` 下 `fetch` 会被 CORS 拦截 |
| 阶段划分 | ZigZag 拐点法（10%） | MA20 二分法 | 二分法产生 13 段且标签与收益矛盾；ZigZag 直接刻画趋势段边界 |
| 品牌色 | 冷调金融蓝 | 生成器默认的暖色调 | 避免与「红涨」语义冲突 |
| 图表库 | ECharts 完整构建 | 轻量 SVG 自绘 | 需要蜡烛图、双栅格联动、dataZoom，自绘成本过高 |
| 截图方式 | Playwright + 本机 Chrome | 手工截图 | 可同时抓控制台报错，把「看起来正常」变成「断言通过」 |
