## 第 4 轮 · 四项任务的计算口径

### 🤖 Agent

写 `scripts/02_analyze.py` 前，先明确几个口径选择，这些都是要写进对话流的决策：

| 口径问题 | 选择 | 理由 |
|---|---|---|
| 相关系数用 Pearson 还是 Spearman | Pearson | 教材语境下默认线性相关；且价格序列单调性强，两者结论方向一致 |
| 日期列是否参与相关 | 排除 | 日期是非定量变量，转成序号算相关无经济含义 |
| 时序图是否叠加均线 | 叠加 MA20/MA60 | 教材只要求收盘价，但单看折线无法判断趋势级别，均线是必要的补充 |
| **均线用哪个区间计算** | **用全样本算再切 2023 段** | 若只用 2023 数据算 MA60，前 59 天全是空值；用全样本算能让 2023 年初的均线有意义 |
| K 线图坐标顺序 | ECharts 约定 `[open, close, low, high]` | 与 OHLC 的常规顺序不同，写错会导致影线和实体错位 |

> **🔍 判断点（主动修正）**：教材任务 (2) 只要求「计算变量之间的相关系数」，但 10 个变量里，
> 开盘/收盘/最高/最低 四列之间必然接近 1.0，成交额与换手率必然接近 1.0——
> 这是**口径决定的恒等关系**，不是发现。
> 如果只画一张热力图，很容易得出「股价和最高价高度相关」这种废话结论。
> 因此额外补一个「日频变动口径」的对照矩阵，并在页面上直接标注哪些格子是结构性冗余。

### 🔧 工具调用 · `python scripts/02_analyze.py`

```
载入 928 行，区间 2023-01-03 ~ 2026-11-04
2023 全年 242 行 | K线区间 59 行 (2023-04-03 ~ 2023-06-30)
已写出 data\analysis.json（96 KB）

区间画像：
  2023-01-03 收盘 261.73 -> 2026-11-04 收盘 266.62，累计 1.87%
  最高 410.49（2025-05-23）  最低 169.4（2024-02-02）
  年化波动 30.75%  最大回撤 -44.56%

K线区间 2023-04-03 ~ 2023-06-30（59 根）
  257.17 -> 259.52，区间 0.91%
  最高 277.11（2023-06-16）  最低 239.02（2023-04-13）
```

### 🤖 Agent

**这里出现了一个反直觉的结果，是整份分析的核心洞察：**

四年走完，累计涨幅只有 **+1.87%**——几乎原地踏步。但同期最高 410.49、最低 169.40，最大回撤 **-44.56%**。

终点回到起点，过程却极不平坦。如果只看「四年涨了 1.87%」这一句，会严重误判这只票的风险特征。

这个结论也决定了我后面不会再补「买入/卖出」之类的判断——AGENTS.md 第 7 章已经写明不得给买卖建议。

### 🔧 工具调用 · 相关系数矩阵交叉核对

```
价格水平口径        开盘   收盘   最高   最低  成交量  成交额   振幅  涨跌幅  涨跌额  换手率
开盘              1.00  0.99  1.00  1.00   0.34   0.56   0.01  -0.03  -0.03   0.31
收盘              0.99  1.00  1.00  1.00   0.36   0.58   0.04   0.06   0.06   0.34
成交额            0.56  0.58  0.60  0.55   0.70   1.00   0.63   0.23   0.22   0.95
换手率            0.31  0.34  0.35  0.30   0.70   0.95   0.73   0.27   0.25   1.00
```

三段可直接写进结论的观察：

1. **价格四列 0.99~1.00** —— 结构性必然，不是独立信息。
2. **成交额 × 换手率 0.95** —— 成交额 ≈ 均价 × 成交量、换手率 ≈ 成交量 ÷ 流通股本，共同由成交量驱动，同样是口径共线。
3. **成交量 × 价格 0.34~0.36** —— 这是矩阵里少数**非冗余**的格子。放量不等于高价，量价关系需要单独分析。

| # | 引擎给的 | 问题 | 修正 |
|---|---|---|---|
| 1 | bg `#F9F6F6`（带红底） | 整页偏红，与「红涨绿跌」的语义色互相干扰，看久了会误读涨跌 | 改中性冷灰 `#F5F6F8`，让红绿只在需要表达涨跌的地方出现 |
| 2 | primary `#A74444` | 红色主色若同时用于「涨」，图表里所有红色都会变得含义模糊 | 主色加深为 `#8C2F39`，**只用于品牌与标题装饰，不参与涨跌语义**；涨跌色独立定义为 `#D9342B` / `#10995A` |
| 3 | 字体 Inter | Inter 不含中文字形，中文会回退到浏览器默认宋体/思源，字重与西文不一致，页面会显得「半洋半土」 | 改系统 UI 字体栈：`Inter, PingFang SC, Microsoft YaHei, system-ui`，数字用 `tabular-nums` 保证列对齐 |

> 第三点还有个隐性收益：Inter 若走 Google Fonts CDN，会引入外网依赖并触发字体加载导致的 CLS（布局偏移），正好违反引擎自己给的 P0 门禁 UX-018。本地化字体栈同时解决了视觉一致性和性能两个问题。

### 🤖 Agent · 可视化方案取舍

| 图表 | 候选 | 选择 | 理由 |
|---|---|---|---|
| 收盘价时序 | 折线 / 面积图 / 蜡烛图 | **折线 + MA20/MA60** | 教材要看的是「全年走势趋势」，K 线信息密度过高反而看不清趋势；均线用来标注趋势级别 |
| 2023 全年时序 | 12 个月柱状 / 折线 | **折线** | 日频数据用柱状会变成 242 根密集竖线，不可读 |
| K 线 | 蜡烛图 / OHLC 棒 | **蜡烛图 + 成交量副图** | 教材明确要求 K 线；成交量副图用于验证「放量突破」这类判断 |
| 相关系数 | 表格 / 热力图 / 网络图 | **热力图** | 教材明确要求；10×10 用颜色编码比数字表更快识别区块 |
| 热力图配色 | 单色渐变 / 红蓝发散 | **红蓝发散**（负蓝-零白-正红） | 矩阵含轻微负值（-0.03），单色无法表达正负；零附近为白，能一眼看出哪些格子「几乎无关」 |

**关于 Y 轴**：时序图纵轴**不从 0 起**（2023 年收盘价在 187~305 之间，从 0 起会把波动压成一条平线）。但这是有代价的——视觉上会放大波动幅度。所以在图卡右上角直接标注了「纵轴不从 0 起，以保留价格波动细节」，把这个选择透明化。

> **✅ 考核点 (4) 可视化选择达成点**：图表形式、配色方案、Y 轴基线、均线区间均有明确的取舍理由，且把「为什么不用另一个」写进了对话。

### 🔧 工具调用 · 重新诊断网络

上一轮已经判定「GitHub 不可达」，这轮换了个角度重测，结果推翻了原结论：

```
DNS        github.com -> 20.205.243.166        （解析正常）
curl 直连   -> 000
git ls-remote ->
  fatal: unable to access 'https://github.com/...':
  schannel: next InitializeSecurityContext failed:
  CRYPT_E_NO_REVOCATION_CHECK (0x80092012)
  — 吊销服务器无法检查证书是否已吊销
```

**关键判断：`CRYPT_E_NO_REVOCATION_CHECK` 不是网络不通，是 Windows schannel 在做证书吊销检查（CRL/OCSP）时连不上吊销服务器，导致 TLS 握手被自己掐断。** 上一轮把 000 直接读成「墙」，是误判。

验证方式：跳过吊销检查再试。

```
curl --ssl-no-revoke https://github.com        -> 200
curl --ssl-no-revoke https://api.github.com    -> 200
GIT_SSL_NO_VERIFY=1 git ls-remote .../Hello-World.git
  -> 7fd1a60b01f91b31...  refs/heads/master   （成功）
```

顺带排除了另一条路：`git -c http.sslBackend=openssl` 会报 `unable to get local issuer certificate`，因为 PortableGit 的 OpenSSL 没有配置 CA bundle。相比之下 `GIT_SSL_NO_VERIFY=1` 更直接，代价是跳过证书校验——用于个人作业仓库可以接受，但需明确记录这个取舍。
